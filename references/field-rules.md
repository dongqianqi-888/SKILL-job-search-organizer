# 字段口径与状态判定标准

本文件定义 9 列整理表（collect 式结构）字段的判定口径与边界示例，保证多批核查结果可合并、口径一致。

## 1. 批次

- 数字编号：第几批核查。
- 新建表从 1 开始；追加进已有表时取表内最大批次 +1。
- 同一张表中不同批次的列结构必须完全一致（9列）。

## 2. 公司

- 使用官方完整名称；海外公司可附英文名（如"ITG 国贸股份（厦门国贸）"、"MERCURIA 摩科瑞"、"高知特 Cognizant"）。
- 集团与子公司并存时以招聘主体为准（如"ABB（中国）ABB Robotics"与"ABB"分属不同批次时各自成行，备注注明关系）。
- 名称来自截图但无法与官网主体对应的，先按官网核实后的名称写，截图名写进备注。

## 3. 官网/招聘入口

优先级：
1. 校招页 URL（`/campus`、`campus.公司名.com`、`zhiye.com`、mokahr 校招页等）
2. 官网招聘入口（`/careers`、`/join-us`、官网首页）
3. 均找不到 → 标"—"，备注说明"未找到官方招聘页面"

必须为真实官方域名；不得编造、补全或猜测 URL。第三方聚合站 URL 不作为官网入口写入（可在证据说明中提及）。

## 4. 校招状态

| 状态 | 判定标准 | 示例 |
|---|---|---|
| 有校招 | 官网/官方招聘页存在面向应届生的校招栏目且正在接受投递 | 2027届校招简章开放中 |
| 有校招（已截止） | 校招页面存在但明确标注截止/已关闭 | 校招页提示"2026届已结束" |
| 无校招（仅社招） | 只有社会招聘，无应届生项目 | 招聘页仅社招职位 |
| 部分匹配 | 校招存在，但岗位与目标职能岗仅部分沾边（如偏生产/销售） | 校招岗位偏研发，个别采购岗 |
| 未确认 | 官网无法访问、找不到招聘信息、或信息矛盾无法核实 | 官网 404、仅第三方消息 |

截图/第三方推送声称"已启动校招"只是线索，必须官网核实后才可标"有校招"；官网无法佐证一律标"未确认"。

## 5. 目标职能岗

- 默认口径：**数据、采购、项目、产品、分析**类职能岗（按用户画像可调整，如"数据/分析/研究/产品/采购/项目"）。
- 判定依据：校招岗位名称/职位描述是否明确包含上述职能类别（如"数据分析师""BI工程师""产品经理""采购专员""项目管理培训生""市场分析"）。
- 有：有明确的该类岗位。
- 无：岗位全部为研发/工程/生产/销售/职能支撑（HR/财务/行政）类。
- 部分：有近似岗位（如"数字化方向""管培生含轮岗数据分析"）或仅个别沾边岗位。
- 未确认：**已完成下述①②仍无法核实**才标未确认（官网无岗位清单可判定，且无官方简章转载可印证）。
- 研发类岗位（IC设计、算法、工艺、测试等）默认不计入目标职能岗，除非用户画像明确需要技术岗。

### 判定执行规范（能查尽查）

1. **证据分级**：官网校招页岗位清单（最强）> 高校就业网转载的官方简章（多源一致可判定，证据列注明"高校就业网转载官方简章"）> 其他第三方聚合站（仅线索，标"第三方称…"，不得单独判定"有"）。
2. **查证顺序**：① 抓官方岗位清单 → ② 清单不可抓时检索高校就业网转载的官方简章交叉印证 → ③ ①②完成后仍无证据才标"未确认"。
3. **未确认纪律**：标"未确认"时证据列必须写明已尝试的途径（如"官方岗位列表JS渲染不可抓，无官方简章转载"），防止因执行深度不足而过早标注。
4. **多源一致**：多家高校就业网转载内容一致的官方简章，视为官方证据的可信复现，可用于判定"有/无/部分"。

## 6. 证据说明

- 写"岗位名 + 栏目名 + 地点 + 来源"的最小可核验信息，如："2027届简章含 AI 产品经理（杭州）、数据工程师（上海），来源官网校招页"。
- 注明来源页面；URL 与第3列一致或指向更具体页面。
- 不写无法定位的断言；信息来自第三方聚合站的需标注"第三方称…"。

## 7. 地点/可投性

- 写岗位主要工作地点；标注是否命中用户期望区域（如"上海/杭州/江浙"、"海外"、"马来西亚"）。
- 影响可投性的因素（已截止、仅社招、主体存疑）写进第8列备注而非本列。

## 8. 备注

- 用户画像相关提示（如"与大宗行研背景契合"、"AI产品经理对口数据产品意向"）。
- 截止时间提醒、主体存疑提示、投递渠道提示、同名歧义说明。

## 9. 适配等级

判定综合三要素：**目标职能岗 × 地点可投性 × 用户简历匹配度**。

| 等级 | 判定口径 |
|---|---|
| 高适配 | 有明确目标职能岗 **且** 地点命中期望城市/可接受地点 |
| 中高适配 | 有目标职能岗但地点不完全命中；或有近似岗位（数字化/管培/供应链数据）+ 地点命中 |
| 中适配 | 有职能岗但数据/分析类不明确，或地点不匹配；或机构研究类岗位与研究方向相关 |
| 低适配 | 无目标职能岗（纯研发/工程/生产/销售）；或已截止/主体存疑/地点不可接受 |

- 等级不随批次变化；同一公司多批次出现时等级保持一致。
- 同等级内部保持核查顺序，不重新打散（除非用户要求）。
- "未确认"状态的公司默认低适配（无法核实 = 不可投递依据），备注说明"待核实"。

## 排序规则

1. 批次升序（1→2→3…）
2. 批次内适配等级降序：高适配 > 中高适配 > 中适配 > 低适配
3. 同等级保持原核查顺序（稳定排序）
